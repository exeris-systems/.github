# ADR-087 — `exeris-bot`, the CI publication and capture step (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-087-establish-exeris-bot-as-the-ci-publication-and-capture-step.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-087-establish-exeris-bot-as-the-ci-publication-and-capture-step.md)

ADR-087 gives the L2 review an output contract and one identity to publish it under: two GitHub Apps
(§A.1), a produce step that writes a `verdict` and a publish step that posts, labels and gates it
(§B.5–B.10), and a capture step that emits one ADR-086 run record per L2 run (§C).

## Why this stub exists

This repository holds the enforcement the ADR describes. Its Engineering Protocol 2 and 3 land here:
the composed verdict schema over the vendored `exeris-agents` base (§B.6a), the label mapping
`labels-from-verdict.json` (§B.7), the produce and publish split of `docs-review.yml` (§B.5), and the
closing requirement in `docs-guardrails-review.md` (§B.6). A reader who finds a `verdict` schema or a
label map in this repository and asks what decided their shape is asking about ADR-087.

The ADR is `draft` in the registry, and Engineering Protocol 9 flips that cell from its accepting
pull request in `exeris-docs`, not from here.
